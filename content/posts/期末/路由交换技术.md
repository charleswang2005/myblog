## 第一次作业、设备管理（vty嵌套）
![](https://charleswang.top/oss/blog/20260918125941098.png)
以上网络拓扑结构是某单位的二层网络，员工出差后单位网络需要调整，员工需要通过远程访问网络设备进行维护，其中两台路由器需要配置SSH协议、交换机配置TELNET协议，实现远程设备的维护。Cloud1需要根据自己的计算机的网络连接进行配置桥接到AR1接口上。通过SSH协议远程到AR1后，再通过AR1进行SSH连接到AR2上，再经过AR2进行TELNET连接到交换机LSW1上。
注意：cloud1绑定的网络连接是自己计算机的vmnet 8，AR1连接cloud1的接口地址为vmnet 8的同网段地址（与本题的地址不一定相同）请根据具体需求，进行协议配置，并通过第三方软件（SecureCRT）进行对应协议的连接进行访问，同时通过抓包分析具体的协议工作过程。全程开摄像头正对自己，边操作边讲解，录制屏幕后以视频文件的方式进行提交（不是压缩文件！），无讲解不得分！第一句：我是XXXX班的XXXXX,下面。。。。。。。。。。。。。。
### **第 1 步：搭拓扑 + 配 Cloud1**
**总体说明**：这一步完成两件事——把四台设备拖到拓扑里，再把 Cloud1 的网桥配好。Cloud1 必须先配好 IO 再连线，否则接口没配好，连不上。
**操作**：
1. 打开 eNSP，新建拓扑。
2. 拖入 **1 个 Cloud**、**2 台路由器（AR1、AR2）**、**1 台交换机（LSW1）**。
3. **先配 Cloud1**：双击 Cloud1，打开 IO 配置：
    - 绑定信息先选 **UDP**，再选 **vmnet8**。
    - 两个绑定编号分别设为 **1 和 2**，设置 **1↔2 双向通信**，点增加。
4. **再连线**（选 Auto）：
    - Cloud1 → AR1（GE 0/0/0）
    - AR1（GE 0/0/1）→ AR2（GE 0/0/0）
    - AR2（GE 0/0/1）→ LSW1（GE 0/0/1）
5. 确认自己电脑 vmnet8 的 IP（控制面板→网络连接→VMware Network Adapter VMnet8），记下网段，下一步 AR1 配地址要用。
### **第 2 步：配置 AR1**
**总体说明**：AR1 是嵌套入口，物理机第一个就登它。这步要做的事：改设备名 → 关提示 → 配两个接口 IP → 开 SSH 服务 → 创建密钥 → 建 SSH 用户 → 配 VTY 通道 → 开启 SSH 客户端功能（后面才能主动连 AR2）。
**操作【逐条执行】**：
```
<Huawei>sys                                     // 切到系统视图，才能改配置
[Huawei]sysname AR1                             // 改名，嵌套登录时提示符变[AR1]，便于区分
[AR1]undo info-center enable                    // 关日志弹窗，终端更干净
[AR1]int g0/0/0                                 // 进入 GE 0/0/0 接口视图
[AR1-GigabitEthernet0/0/0]ip add 192.168.221.3 24  // 配IP，必须和vmnet8同网段，物理机才能连
[AR1-GigabitEthernet0/0/0]q
[AR1]int g0/0/1                                 // 进入 GE 0/0/1，这个口连 AR2
[AR1-GigabitEthernet0/0/1]ip add 1.1.1.1 24    // 和 AR2 同网段才能互连
[AR1-GigabitEthernet0/0/1]q
[AR1]stelnet server enable                      // 开启 SSH 服务，默认关
[AR1]rsa local-key-pair create                  // 生成密钥对，SSH 加密握手必须
[AR1]aaa                                        // 进入 AAA 视图，用来建用户
[AR1-aaa]local-user kkk privilege level 15 password cipher 12341234  // 建用户kkk，权限最高，密码密文存
[AR1-aaa]local-user kkk service-type ssh        // 这个用户只能用 SSH，不能 Telnet
[AR1-aaa]q
[AR1]user-interface vty 0 4                     // 进入 VTY 虚拟终端（0~4共5个通道）
[AR1-ui-vty0-4]authentication-mode aaa          // 认证用 AAA（用户名+密码）
[AR1-ui-vty0-4]protocol inbound ssh             // 只允许 SSH 从 VTY 进，拒绝 Telnet
[AR1-ui-vty0-4]q
[AR1]ssh client first-time enable               // 允许 AR1 首次连接未知主机，后面才能 SSH 到 AR2
```
### **第 3 步：配置 AR2**
**总体说明**：AR2 是中间跳板，既要被 AR1 SSH 登录，又要 Telnet 到交换机。步骤和 AR1 基本相同，但有两点不同：① 接口 IP 不一样（1.1.1.2 连 AR1，2.2.2.1 连交换机）② 多了 `ssh user` 那行。
**操作【逐条执行】**：
```
<Huawei>sys
[Huawei]sysname AR2                             // 改名
[AR2]undo info-center enable
[AR2]int g0/0/0
[AR2-GigabitEthernet0/0/0]ip add 1.1.1.2 24    // 连 AR1，同网段
[AR2-GigabitEthernet0/0/0]q
[AR2]int g0/0/1
[AR2-GigabitEthernet0/0/1]ip add 2.2.2.1 24    // 连交换机，同网段
[AR2-GigabitEthernet0/0/1]q
[AR2]stelnet server enable
[AR2]rsa local-key-pair create
[AR2]aaa
[AR2-aaa]local-user qqq privilege level 15 password cipher 12341234  // 用户 qqq
[AR2-aaa]local-user qqq service-type ssh
[AR2-aaa]q
[AR2]user-interface vty 0 4
[AR2-ui-vty0-4]authentication-mode aaa
[AR2-ui-vty0-4]protocol inbound ssh
[AR2-ui-vty0-4]q
[AR2]ssh user qqq authentication-type password  // ← 和 AR1 不同！指定 qqq 用密码认证，否则登不进
```
### **第 4 步：配置 LSW1（交换机）**
**总体说明**：交换机是二层设备，物理口不能配 IP，要用 VLANIF 虚拟接口配。最后一步从 AR2 Telnet 到这里，所以开 Telnet 服务。
**操作【逐条执行】**：
```
<Huawei>sys
[Huawei]sysname SW1
[SW1]undo info-center enable
[SW1]int vlan 1                                 // ← 和路由器不同！交换机用 vlanif 配三层地址
[SW1-Vlanif1]ip add 2.2.2.2 24                 // 配在虚拟接口上，物理口没有 IP
[SW1-Vlanif1]q
[SW1]aaa
[SW1-aaa]local-user ppp privilege level 15 password cipher 12341234
[SW1-aaa]local-user ppp service-type telnet     // ← 和路由器不同！用户只能用 Telnet，不是 SSH
[SW1-aaa]q
[SW1]user-interface vty 0 4
[SW1-ui-vty0-4]authentication-mode aaa
[SW1-ui-vty0-4]protocol inbound all             // ← 和路由器不同！允许所有协议，因为只开了 Telnet
```
### **第 5 步：嵌套登录验证**
**总体说明**：按物理机→AR1→AR2→LSW1 的顺序一步步跳转，展示每跳成功后的提示符。
**第 1 跳：物理机 → AR1（SSH）**
- SecureCRT → 协议 SSH2 → 地址填 AR1 的 GE 0/0/0 地址（192.168.221.3 或你配的 vmnet8 同网段地址）→ 用户名 `kkk`，密码 `12341234`。
- 提示符变成 `[AR1]`。
**第 2 跳：AR1 → AR2（SSH 嵌套）**
```
[AR1]stelnet 1.1.1.2               // stelnet = SSH 客户端命令，目标 AR2 的地址
``

→ 输入用户名 `qqq`，密码 `12341234`。
- 提示符变成 `[AR2]`。
**第 3 跳：AR2 → LSW1（Telnet）**  
先输入 `q` 退到 AR2 的用户视图（提示符变 `<AR2>`），然后：
```
```
<AR2>telnet 2.2.2.2                // ← telnet 必须用户视图执行，系统视图会报错
```
→ 输入用户名 `ppp`，密码 `12341234`。
- 提示符变成 `[SW1]`，链路打通。
### **第 6 步：抓包分析**
**总体说明**：分两次抓包，对比 Telnet（明文）和 SSH（加密）的区别。Telnet 流量在 AR2—LSW1 之间，SSH 流量在 Cloud1—AR1 之间，两条链路分开抓。
**6.1 抓 Telnet 明文**
**操作**：
1. 右键 **AR2 与 LSW1 之间的连线** → 开始抓包。
2. 从 AR2 重新执行一次 `telnet 2.2.2.2`，慢慢输入 `ppp`、`12341234`，登录成功后停止抓包。
3. 过滤栏输入 `telnet` 回车。
4. 选中一个靠后的包 → 右键 → **Follow → TCP Stream**。
5. 弹窗里看到 `Login: ppp`、`Password: 12341234`。
**6.2 抓 SSH 加密包**
**注意：SSH 全程加密，TCP Stream 弹出来也是乱码，没法展示对比效果。正确做法是看 Info 列的 `Encrypted packet` 标志。】
操作**：
6. 右键 **Cloud1 与 AR1 之间的连线** → 开始抓包。
7. 物理机重新用 SecureCRT SSH 登录 AR1（kkk、12341234）。
8. 停止抓包，过滤栏输入 `sshv2` 回车。
9. 观察 Info 列：所有包显示 **`Encrypted packet`**，协议列显示 **`SSHv2`**。
10. 双击展开一个包的数据载荷区域：显示的是加密后的乱码数据。
**对比结论说**：「Telnet 明文传输，SSH 全程加密，所以生产环境应该用 SSH 替代 Telnet。」
# 第二次作业、网络综合部署实验试题作业（*）

## 任务 ① 基础 VLAN 配置
**涉及设备与连线**：S3（E0/0/1~E0/0/4 接 PC1~PC4）；S1、S2 只创建 VLAN，暂不配接入端口；S4 创建 VLAN3 。
**S3 上敲（双击 S3 → 命令行）**
```
[S3]vlan batch 4 5 6 7
```
批量创建 VLAN4、5、6、7，对应市场部、人事部、运维部、生产部 。
```
[S3]interface Ethernet0/0/1
```
进入接 PC1 的百兆电口视图（接入交换机接终端统一用 E 口）。
```
[S3-Ethernet0/0/1]port link-type access
```
把端口设为 access 类型，只承载单个 VLAN 的无标记帧。
```
[S3-Ethernet0/0/1]port default vlan 4
```
把该口划入 VLAN4，PC1 即归属于市场部网段 10.1.4.0/24 。
```
[S3-Ethernet0/0/1]undo shutdown
```
激活端口，eNSP 中部分口默认管理关闭会导致不通。
其余三口同理，逐口敲：
```
[S3-Ethernet0/0/1]interface Ethernet0/0/2
[S3-Ethernet0/0/2]port link-type access
[S3-Ethernet0/0/2]port default vlan 5
[S3-Ethernet0/0/2]undo shutdown
```
PC2 归入 VLAN5（人事部 10.1.5.0/24）。
```

## 任务 ③ S4 交换机 MUX VLAN（服务器区）

**涉及设备与连线**：S4 的 G0/0/1 上行接 SZ1（主 VLAN3）；G0/0/3→FTP1、G0/0/4→FTP2、G0/0/5→Web、G0/0/6→Mail 。

**规划**：VLAN3 主 VLAN；VLAN10 互通型从 VLAN（group）承载 FTP1/FTP2；VLAN20 隔离型从 VLAN（separate）承载 Web/Mail 。

### S4 上敲

```

```

创建主 VLAN3、互通型从 VLAN10、隔离型从 VLAN20 。

```

```

[S4-vlan3]quit
[S4]interface GigabitEthernet0/0/1
[S4-GigabitEthernet0/0/1]port link-type access
[S4-GigabitEthernet0/0/1]port default vlan 3
[S4-GigabitEthernet0/0/1]port mux-vlan enable

**FTP1、FTP2 的口必须划入 VLAN10（这是本次排错修正点，划成 VLAN20 会导致两台 FTP 互 ping 全失败）**：

```

[S4-GigabitEthernet0/0/3]port link-type access
[S4-GigabitEthernet0/0/3]port default vlan 10
[S4-GigabitEthernet0/0/3]port mux-vlan enable
```

```
[S4-GigabitEthernet0/0/3]interface GigabitEthernet0/0/4
[S4-GigabitEthernet0/0/4]port link-type access
[S4-GigabitEthernet0/0/4]port default vlan 10
[S4-GigabitEthernet0/0/4]port mux-vlan enable
```

G0/0/4 接 FTP2，同属互通型从 VLAN10 。

**Web、Mail 的口必须划入 VLAN20，且不能漏配（漏配会导致 PC ping 不通这两台服务器）**：

```
[S4-GigabitEthernet0/0/4]interface GigabitEthernet0/0/5
[S4-GigabitEthernet0/0/5]port link-type access
[S4-GigabitEthernet0/0/5]port default vlan 20
[S4-GigabitEthernet0/0/5]port mux-vlan enable
```

G0/0/5 接 Web，划入隔离型从 VLAN20 。

```
[S4-GigabitEthernet0/0/5]interface GigabitEthernet0/0/6
[S4-GigabitEthernet0/0/6]port link-type access
[S4-GigabitEthernet0/0/6]port default vlan 20
[S4-GigabitEthernet0/0/6]port mux-vlan enable
```

G0/0/6 接 Mail，同属隔离型从 VLAN20，与 Web 二层隔离 。

**改 VLAN 的坑（本次实测踩过）**：如果某口已经敲过 `port mux-vlan enable`，再直接敲 `port default vlan X` 会报 "Please disable MUX-VLAN on the port first"。此时必须在接口视图下按此顺序处理：

```
[S4-GigabitEthernet0/0/3]undo port mux-vlan enable
```

先关闭该口的 MUX 功能，解除改 VLAN 的限制。

```
[S4-GigabitEthernet0/0/3]port default vlan 10
```

解除限制后再修改端口所属 VLAN。

```
[S4-GigabitEthernet0/0/3]port mux-vlan enable
```

最后重新启用 MUX 功能，使该口重新参与 MUX 策略 。

[S1-ip-pool-vlan7]gateway-list 10.1.7.1
[S1-ip-pool-vlan7]excluded-ip-address 10.1.7.252 10.1.7.253
[S1-ip-pool-vlan7]dns-list 8.8.8.8
[S1-ip-pool-vlan7]quit
```

VLAN5/6/7 三个池按同样结构建立，网关分别填各自的 VRRP 虚拟 IP，并排除 .252/.253 。

```
[S1]interface Vlanif 4
[S1-Vlanif4]dhcp select global
```

VLANIF4 下采用全局地址池方式分配，收到请求时按接口网段匹配全局池 。

```
[S1-Vlanif4]interface Vlanif 5
[S1-Vlanif5]dhcp select global
[S1-Vlanif5]interface Vlanif 6
[S1-Vlanif6]dhcp select global
[S1-Vlanif6]interface Vlanif 7
[S1-Vlanif7]dhcp select global
```

四个业务 VLANIF 全部启用全局池方式 。

### S2 上敲

```
[S2]dhcp enable
```

开启 S2 的 DHCP 功能 。

```
[S2]ip pool vlan6
[S2-ip-pool-vlan6]network 10.1.6.0 mask 24
[S2-ip-pool-vlan6]gateway-list 10.1.6.1
[S2-ip-pool-vlan6]excluded-ip-address 10.1.6.252 10.1.6.253
[S2-ip-pool-vlan6]dns-list 8.8.8.8
[S2-ip-pool-vlan6]quit
[S2]ip pool vlan7
[S2-ip-pool-vlan7]network 10.1.7.0 mask 24
[S2-ip-pool-vlan7]gateway-list 10.1.7.1
[S2-ip-pool-vlan7]excluded-ip-address 10.1.7.252 10.1.7.253
[S2-ip-pool-vlan7]dns-list 8.8.8.8
[S2-ip-pool-vlan7]quit
```

S2 本地建立 VLAN6/7 的全局池（S2 是这两组的 VRRP Master），不使用中继，规避中继回程不通 。

```
[S2]interface Vlanif 6
[S2-Vlanif6]dhcp select global
[S2-Vlanif6]interface Vlanif 7
[S2-Vlanif7]dhcp select global
```

S2 的 VLANIF6/7 采用本地全局池分配 。

补充：若 S1 故障时也要让 S2 接管 VLAN4/5 的地址分配，可在 S2 上同样建立 vlan4、vlan5 池并把可分配范围错开（例如排除 .1 到 .200）后再 `dhcp select global`，避免两侧分出重复地址 。

## 四、断链冗余所需的备份路由（验证 4 的前提）

S1 上行 Vlanif12 断开后，S1 上原有到 10.3.1.0/24 的下一跳 10.2.12.1 会失效，必须提前准备备份路径，否则 VLAN4/5 的跨网段业务会中断。

S1 上敲：

```
[S1]ip route-static 10.3.1.0 255.255.255.0 10.1.4.253 preference 100
```

配置到服务器网段的备份路由，下一跳为 S2 的 Vlanif4 地址 10.1.4.253，优先级 100 低于主路由的 60，主路正常时不上表 。

SZ1 上敲：

```
[SZ1]ip route-static 10.1.4.0 255.255.255.0 10.2.13.2 preference 100
[SZ1]ip route-static 10.1.5.0 255.255.255.0 10.2.13.2 preference 100
```

为 VLAN4/5 配置回程备份路由，下一跳为 S2 的 10.2.13.2，优先级 100，主路断时经 S2 回程 。

## 五、五项连通性验证

### 验证 1：PC 之间跨 VLAN 互通

操作：双击 PC4 → "命令行"页签 → 敲 `ping 10.1.4.x`（PC1 获取到的地址）。

判定语句：PC4 与 PC1 分属 VLAN7 与 VLAN4，互 ping 收到应答，PC 跨 VLAN 互通成立 。

### 验证 2：PC 可以访问 4 台服务器

操作：双击 PC4 → "命令行"页签 → 依次敲 `ping 10.3.1.100`、`ping 10.3.1.101`、`ping 10.3.1.102`、`ping 10.3.1.103` 。

判定语句：PC4 对四台服务器地址的 ping 均有应答，PC 访问服务器成立 。

### 验证 3：FTP1 与 FTP2 互通，Web 与 Mail 二层隔离

操作一：双击 FTP1 → "命令行"页签 → 敲 `ping 10.3.1.101` 。

判定语句：FTP1 ping FTP2 五个包全部收到应答，互通型从 VLAN10 内互访成立 。

操作二：双击 Web → "命令行"页签 → 敲 `ping 10.3.1.103`，目的必须是 Mail 自身的 10.3.1.103，不能填网关 10.3.1.254 。

判定语句：Web ping Mail 五个包全部超时无应答，隔离型从 VLAN20 内二层隔离成立 。

### 验证 4：断开 S1 上行，VLAN4、5 业务切到 S2 不中断

操作一：双击 PC1 → "命令行"页签 → 敲 `ping 10.3.1.100 -t`，持续 ping 服务器地址 。

操作二：点左侧"设备连线"图标（断线模式）→ 单击 S1 G0/0/1 与 SZ1 G0/0/1 之间的那条线，使其断开 。

操作三：在 S1 上敲 `display ip interface brief`，确认 Vlanif12 变为 down，证明断的是正确的链路。

操作四：回到 PC1 的命令行窗口观察回显。

判定语句：断链瞬间出现少量超时，随后恢复应答，VLAN4、VLAN5 业务经 S2 上行转发，网络不中断成立 。

操作五：再次点"设备连线"图标，重新连接 S1 G0/0/1 与 SZ1 G0/0/1，恢复拓扑后再做验证 5 。

### 验证 5：查看 MSTP，确认冗余链路被阻塞，无广播环路

操作：在 S3 上敲 `display stp instance 1 brief` 与 `display stp instance 2 brief`；在 S1 上敲 `display stp instance 2 brief`；在 S2 上敲 `display stp instance 1 brief` 。

判定语句：实例 1 中 S3 上行 S1 的口为 ROOT 转发、上行 S2 的口为 ALTE 阻塞 。

判定语句：实例 2 中 S3 上行 S2 的口为 ROOT 转发、上行 S1 的口为 ALTE 阻塞 。

判定语句：两条上行链路在任一实例下只有一条转发、另一条被阻塞，物理环路在逻辑上被剪断，广播环路不存在 。
